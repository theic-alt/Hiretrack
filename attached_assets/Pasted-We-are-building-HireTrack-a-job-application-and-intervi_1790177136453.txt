DAY 2 — JOB APPLICATION BACKEND

Create a REST API for job applications.

Required endpoints:

GET /api/health

GET /api/applications
- Return the current user's applications.
- Sort newest/most recently updated first.

GET /api/applications/:id
- Return one application.

POST /api/applications
- Create an application.
- Validate required fields.
- companyName and jobTitle are required.
- status must be one of the supported statuses.

PATCH /api/applications/:id
- Update an application.
- Validate the data.

DELETE /api/applications/:id
- Delete an application.

Use proper HTTP status codes:
- 200 for successful GET/PATCH
- 201 for successful POST
- 204 for successful DELETE
- 400 for invalid input
- 404 when the application doesn't exist
- 500 for unexpected server errors

Keep database queries on the server.
Do not allow the frontend to directly access the database.
